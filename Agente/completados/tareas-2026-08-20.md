- **Decisiones / gotchas:**
  - **Arquitectura:** se descartó hardcodear posts en el frontend porque el backend ya
    tiene blog + API + editor administrativo; el contenido seed es editable desde el
    panel y el frontend solo renderiza lo que devuelve la API.
  - El proxy del frontend apuntaba a `3000` (backend de otro proyecto) → la sección
    mostraba el estado de error (correcto, sin fallo silencioso). Se reinició el dev
    server con `BACKEND_PROXY=http://localhost:3010`.
  - Las imágenes `/imagenes/01-03.webp` ya existían en `public/imagenes/` y son
    verticales; se usó `aspect-ratio: 3/2` para no recortarlas a una franja.
  - **Gotcha de BD (resuelto):** la migración seed original escribía `\n\n` literal en
    el body y Postgres (con `standard_conforming_strings = on`) lo guardaba como
    backslash+n, no como salto de línea. La migración ahora usa `E'...'` (escape
    estándar) para futuras instalaciones, y se actualizó el body en la BD actual
    (`ong_agame_backend_ong_agape`, `replace(body, '\\n', E'\n')`, 3 filas). El
    componente `HistoriaDetalle` además normaliza `\n` por robustez.
  - VarSense reporta "valores hardcodeados" y "box-shadow" en `BlogInicio.css`, igual
    que en `AcercaDeNosotros.css` aprobado → consistencia del sistema, no son defectos
    nuevos.

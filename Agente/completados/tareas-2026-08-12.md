## 128A-1 — Frontend v2: scaffold listo y vacío (lo construye el usuario)
- **Que:** Se creó `frontend-v2/` (React 18 + Vite 5 + TS) con scaffold mínimo listo
  para construir, dejando `frontend/` intacto como referencia. Primero se construyó una
  landing de ejemplo completa (sistema de diseño, componentes atómicos, clientes API,
  secciones) y se validó en el navegador; a petición del usuario ese contenido se
  eliminó y el frontend v2 quedó **vacío** para que el usuario lo construya desde cero.
- **Archivos:** `frontend-v2/` (`package.json`, `vite.config.ts`, `tsconfig.json`,
  `index.html`, `src/main.tsx`, `src/App.tsx` placeholder, `src/vite-env.d.ts`),
  `.gitignore` (ignores de `frontend-v2/`), `.env` (local, credenciales de desarrollo),
  `.cargo/config.toml` (local, target en `C:\tmp\glory-target`),
  `Agente/planes/plan-frontend-v2-2026-08-12.md`.
- **Evidencia:** con el scaffold vacío, `npm run type-check` OK y `npm run build` OK
  (142 kB). La landing de ejemplo llegó a correr en `http://localhost:5176` con datos
  reales del API (transparencia/blog 200 a través del proxy) antes de ser eliminada.
- **Gotchas:** el entorno del agente inyecta `PORT=0` y dotenvy no sobreescribe vars
  existentes → el backend ignora el `PORT=3000` del `.env` y bindea puerto efímero.
  Para puerto fijo: `PORT=3010 node scripts/run-with-db.mjs run`. El puerto 3000 lo
  ocupa `glory-backend.exe` de otro proyecto del área (no se tocó).
- **Sentinel:** no aplica.
- **GLORY:** no aplica (el contenido eliminado era específico del cliente; si en el
  futuro se extrae utilidad agnóstica, irá a `glory-rs`).
